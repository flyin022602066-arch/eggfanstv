# 豆包浏览器视频

eggfansTV 的本地浏览器执行协议。它由宿主维护独立的浏览器环境、原任务回执与生成状态，使用当前环境内的同源画布请求完成视频提交。该协议不是普通网关，也不要求填写 API Key。账号环境池与憨包组件各自保存配置，切换相同模型名称不会将其他渠道的凭据、请求头或环境资料带入此渠道。

## 接口与身份

提交通过本地任务中心创建视频任务，再由宿主调用本地运行层。运行层使用原环境的网页请求参数和会话访问画布服务，不把 Cookie、CSRF 值或网页会话令牌返回管理页面。创建、读取、节点写入和生成分别经过固定接口清单；调用者不能指定任意浏览器请求路径，也不能要求运行层导航到任意上游。查询固定使用该任务保存的工作区、会话、节点和请求身份，不以后来选择的账号替换原环境。

## 模型与参数范围

固定清单包含 Seedance 2.5、Seedance 2.0、Seedance 2.0 Fast 和 Seedance 2.0 Mini，对应原生值分别为 seedance_v2.5、seedance_v2.0_std、seedance_v2.0 和 seedance_v2.0_mini。标准版与 Fast 分别映射，不能只根据显示名称合并。Seedance 2.5 接受一至三十秒整数，其他模型接受一至十五秒整数，默认五秒。画幅支持 16:9、9:16、1:1、4:3、3:4，默认横屏。

## 参数与图片参考

项目和画布沿用统一的视频任务输入。提示词最多四千字符，参考图最多十张，支持 PNG、JPEG、WebP。运行层通过原网页上传服务取得图片回执，再核对资源标识及宽高，按用户参考顺序构造附件。提示词中的引用标记与附件逐一绑定；不存在的引用编号在提交前拒绝。不提供参考视频、参考音频、随机种子、分辨率、负面提示词或未声明的声音开关。上游自身生成声音的行为由上游模型决定，宿主不伪造额外参数。

## 环境维护与清理

启用后至少保存三百个隔离环境编号，浏览器资料按需建立；已有环境池沿用原维护流程补足编号，不替换原环境身份和任务回执。维护每十秒检查池状态，每轮预热少量环境。可复用环境不足时先按原规则清理已交付环境，仍不足则按缺口自动新增编号，三百是基础储备而非硬上限；扩容结果持久保存。分配一个任务前先准备足够网页，分配后仍保留至少两个空闲网页；同一环境不能被两个未完成任务同时使用。生成中、提交未确认和成功待取回环境不因扩容被清理。网页未就绪、浏览器退出或需要人工处理时显示真实状态，不能将本地环境数量解释成真实账号余额。初始化失败后有限频率重新检查，需检查的既有环境计入待处理容量，不因初始化失败无限新增。

用户可手动批量清理本池网站数据。清理前检查全部任务，存在未完成或受理结果未确认的任务就整批拒绝。允许清理时先停止本池专用浏览器，仅删除对应环境的 Cookie、登录态、缓存与网站存储，保留任务回执和环境编号。失败环境单独统计，不以成功数覆盖失败。清理本地资料不能证明恢复服务器额度，因此接口始终明确说明上游额度重置未获确认。

## 官方能力与验证边界

该适配依据已检查的参考客户端协议实现，不属于上游官方公开 API 的承诺。网页版本、登录要求、权限和额度可能改变；遇到变化应显示真实错误并检查原环境。离线测试和本地空白页测试只证明调度、数据保护、参数转换及浏览器通信，不证明上游允许生成。真实视频结果以原画布的成功状态、任务身份和可信媒体地址为准。

## 宿主运行时合同

每个工作区归属使用独立运行进程和资料目录。管理读取不启动浏览器网页；启用、打开环境及清理要求可信桌面写入权限。首次提交先落盘预留，再记录每一步写意图；受理回执先保存到任务与尝试记录，再进入轮询。提交连接断开时保留原环境与检查点，不自动换号重发。恢复入口可查找原任务运行层回执，只继续查询原画布。视频成功后走宿主既有下载、资源保存和项目绑定流程。程序退出时停止本渠道子进程；重新启动只恢复已明确启用的环境池。日志和接口不输出真实网页密钥或用户浏览器资料路径。

环境名称使用持久 UUID，重启和清理后保持稳定。宿主在任务成功前自动归档视频原件至 output/项目/集数；根目录及分类目录按需建立。结果的 localExport 只返回相对路径和 saved 状态。磁盘或归属校验失败保留已下载资源与本地恢复记录，后续只重试归档，不重发视频生成；同一任务复用首次确认的目录，不覆盖不同内容的已有文件。
