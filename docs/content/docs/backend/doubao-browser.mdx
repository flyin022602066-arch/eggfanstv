# 豆包浏览器渠道

在「设置 → 模型管理 → 豆包浏览器 → 账号管理」启用自动维护。该渠道使用 doubao-browser-video 协议，与憨包账号组件分别配置。新环境直接使用网页匿名会话进入原生画布，不需要飞狐取号、API Key 或预先登录豆包。

## 环境与调度

环境池维持至少 100 个独立环境编号，浏览器资料按需建立；已有更多环境的工作区保留原记录，不自动删除。自动维护每 10 秒检查池状态，以小批次预热空闲网页；任务先额外预热一个环境，再预留生成环境，保持另外两个空闲环境。每个环境同时只承载一个任务，最多同时占用 98 个；累计提交次数不是环境终身使用次数。提交时预热失败会继续尝试其他可用候选，而不是前一两个环境异常就判定全池耗尽。单轮准备有时间预算，未就绪环境进入需检查及重试冷却；无法补齐预留环境时不向上游提交，并显示就绪、待预热、需检查和任务占用数量。初始化、登录或网络失败显示「需检查」，异常期间不能保证始终有两个就绪环境。

自动新增环境名称为 eggfansTV 加完整 UUID；不同批次、不同工作区的环境不会复用序号名称。名称与环境编号一并持久保存，重启和清理网站数据不改名；已有序号名或重名记录会按原 UUID 补齐名称，不变更浏览器资料身份及任务回执。该名称是本地环境名称，原生画布标题另外使用唯一任务 ID。

100 个环境表示隔离的本地浏览器资料，不是 100 个已验证身份或已确认额度的上游账号。环境使用 Chrome 或 Edge；程序优先使用随发行包提供的 Node。就绪判断使用同源网页请求参数，不以账号信息接口的未登录状态阻止匿名画布。遇到权限或额度限制时保留真实上游结果。点击「打开环境」可检查未占用环境；维护不会自动关闭用户手动打开的检查窗口。

明确的生成失败和受理前失败会释放环境，不计为成功使用；上游明确提示额度不足的环境则保持拒绝状态，不能假定额度仍可用。旧记录中仅因失败被标记为已用的环境在加载时恢复。失败原任务的结果及回执仍保留，同一任务不会因此重新提交；新任务可轮换使用已释放环境。查询成功但本地尚未完成视频入库与 output 归档的环境标记为「成功待取回」，不可清理。归档成功后由后端写入按工作区隔离的交付确认，才变为「成功待清理」；空闲储备不足时自动小批次清理并复用，避免无限新增浏览器资料。管理页面分别显示成功任务、失败任务、成功待取回、成功待清理、待预热及需检查状态。每个任务的提交与后续查询固定使用原回执中的环境，不在提交不明时换环境重发。

## 视频参数

在项目或画布的视频模型选择中选择「豆包浏览器」下的模型，仍使用 eggfansTV 的任务中心保存、查询及交付视频。

| 模型 | 实际参数 | 时长 |
| --- | --- | --- |
| Seedance 2.5 | seedance_v2.5 | 1～30 秒 |
| Seedance 2.0 | seedance_v2.0_std | 1～15 秒 |
| Seedance 2.0 Fast | seedance_v2.0 | 1～15 秒 |
| Seedance 2.0 Mini | seedance_v2.0_mini | 1～15 秒 |

支持 16:9、9:16、1:1、4:3、3:4；最多十张 PNG、JPEG、WebP 参考图；本地提示词校验上限为 8000 字符，前端、后端及浏览器执行器保持一致，不自动截断。上游实际接受范围以其返回为准。不提供原生协议未声明的分辨率、音频开关、参考视频或参考音频参数。

模型选项表示原生协议映射，不保证每个环境都有全部模型权限。Seedance 2.0 Fast 已通过软件画布的 5 秒、16:9 无人物场景真实生成验证，完成原任务查询、视频取回、资源入库、output 归档和画布播放；其他模型遇到上游拒绝时保留所选模型和错误，不自动换模型。

项目生成设置和画布视频节点提供独立的「自动人脸遮罩」，默认关闭；可选择半透明网格及 50%、60%、75% 密度，或马赛克。画布「人脸遮罩」可预览检测结果并手动框选，设置与框选随节点保存。开启后保留原图，在提交前生成本地处理副本，原生网页上传该副本；关闭则上传原图，不增加上游未声明的 face 参数，也不改变模型或音频参数。该渠道的设置、框选和处理缓存与憨包及其他渠道隔离。上游审核仍可能拒绝图片、文本或其他内容，局部处理不代表审核必定通过。

豆包浏览器另提供「强模糊」和「实色遮挡」两种本地隐私处理。每张参考图的全部已识别或手动框选人脸分别处理，图像尺寸和区域外画面不变；可在画布逐图预览、补框并保存。强模糊会降低脸部细节，实色遮挡会完全去除框内身份信息，可能削弱生成角色的一致性，不保证通过上游审核。这两个选项仅在豆包浏览器渠道启用，不改变其他渠道原有遮罩模式、上传协议或生成参数。

提交前保存环境预留及每一步意图；受理后先保存原任务与环境回执再查询。连接异常时保留原任务身份，恢复只读原画布，不自动换号重发。查询成功后下载并交给现有资源交付流程。未知提交会继续占用其原环境，清理操作自动跳过该环境，不影响其他已结束环境的清理。

原任务失败时同时显示上游业务码和返回的具体原因，不把所有失败归为网络或上传异常。错误文字会隐藏链接和凭据并限制展示长度；上游没有返回具体原因时只显示业务码，不推测审核、额度或模型权限。上游明确拒绝的任务不会自动换环境重发。

画布中已明确结束的失败任务可通过提示词面板的「生成」手动新建任务；确认框显示上次失败原因及可能再次消耗积分的提醒，取消不会提交。自动批量重试仍保留原有审核保护。原任务运行中、提交结果未知或已有结果待取回时不新建任务，避免重复生成和扣费。

## 视频自动下载与归档

原任务返回视频后立即下载完整原件，写入本地资源库用于播放，并自动归档至 output。源码工作区使用项目根目录的 output；独立安装程序使用可执行文件所在目录的 output，不依赖启动时的工作目录。目录不存在时按需创建。

目录结构为 output/项目名-稳定标识/集标题-稳定标识/video-任务标识-序号.mp4。项目、分集和镜头以服务器保存的归属关系核对，画布可通过节点分集或唯一的画布分集关联定位；多集画布不能唯一定位时使用「未分集」，不会猜测集数。独立画布使用画布标题分类。非法文件名字符会替换，标识用于区分同名项目、集数和任务。

归档通过临时 .part 文件写入、校验并改名；同一任务恢复时复用已确定的归档目录，项目改名不会重复输出。已有同名文件只有内容与原件相同才视为已保存，不覆盖不同内容。输出目录不可写时保留已下载资源与恢复记录，任务显示「视频已下载，等待本地 output 归档」，稍后只重试本地归档，不重新提交视频生成。

只有资源入库和归档完成后任务才标记成功。成功结果包含 localExport：status 为 saved、directory 为 output、relativePath 为相对于 output 的视频路径、files 为全部归档相对路径。业务 API 不返回机器绝对路径。原有资源播放 URL 保持不变，不自动补导历史视频。

## 一键清理

「一键清理缓存 / 网站数据」先核对历史成功视频的本地归档，再关闭可释放环境的专用浏览器，清理专用环境中的 Cookie、缓存、网站存储和登录态。清理成功后清除当前已用标记，恢复本地可调度状态并按需预热；重启不再因历史回执重新标成已用。环境编号、名称、历史任务及回执保留。正在生成、提交未确认和成功待取回的环境自动跳过，实际清理失败的环境不参与调度。页面显示成功清理、跳过及失败的真实数量。只清理本渠道 UUID 浏览器资料目录，不删除本地视频、视频缓存、素材库、output 或其他渠道的数据。

清理对应四项：历史记录、网页及着色器缓存、Cookie 与认证信息、网站存储（LocalStorage、SessionStorage、IndexedDB、Service Worker、CacheStorage 和 File System）。先退出专属浏览器以释放认证缓存，再按专属 UUID 目录内的白名单清理；保留环境配置、书签和本地任务回执。不保留网站登录状态。清理前验证路径与目录链接，遇到异常不标记清理成功。

清理本地数据不等于创建新上游账号或重置上游额度。接口固定返回 quotaResetConfirmed: false；页面报告本地可调度恢复，不声称上游额度恢复。清理结果另含 skipped 数量；状态包含 pending、succeeded、failed、cleaned、cleaning，分别表示待取回环境、历史成功任务、历史失败任务、曾清理环境及当前清理活动。

## 管理接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | /api/doubao-browser/status | 读取当前工作区状态，不创建浏览器网页 |
| PUT | /api/doubao-browser/settings | enabled 布尔值启停维护 |
| POST | /api/doubao-browser/open | profileId 打开本池未占用环境 |
| POST | /api/doubao-browser/clear | 空对象批量清理本池网站数据 |

接口沿用业务信封和当前本地工作区身份；写操作还校验桌面写入权限。浏览器资料按归属隔离，管理接口不返回 Cookie、Token 或本地路径。发行时只包含 server.mjs、pool.mjs、engine.mjs，不携带个人环境资料。
