## 安装格式

技能库接受 UTF-8 Markdown 或 ZIP 技能包。标准包入口为 SKILL.md，前置 YAML 包含 name 和 description；版本写在 metadata.version。ZIP 可以包含一层外部目录，辅助文档使用相对路径链接，例如 references/lighting-review.md。普通 Markdown 会作为 SKILL.md 安装。

安装接口为 POST /api/skills/install，使用 multipart/form-data：file 是文件，name、description 可覆盖入口元数据，tag 选择分类，isPrivate 控制公开或仅自己。摄影包使用 drama，即“短剧影视”。安装后当前工作区用户可在“我的技能”使用，并通过详情查看入口、辅助文件和固定版本。

## 摄影技能包

仓库 skill-packages/cinematography 保存四个独立标准包：大师级摄影机位与镜头设计、电影级运镜与场面调度、电影光影设计与精细布光、摄影色彩与画面连续性质检。每包包含一个 SKILL.md 和一份按需读取的参考资料；显示名称与分类在 catalog.json 中声明。它们作为当前本地工作区用户的技能安装，不新增另一套内置 ID。

这些技能不限定生成时长，沿用任务的画幅、风格、对白、资产和输出合同。只提供文本设计及诊断；生成、上传和外部分析仍须由用户明确发起。已有 30 秒专项技能继续保留，适用于原有连续分镜工作流。

Windows 完整外发安装包将这四个标准 ZIP 技能包放在可执行文件旁的 `skill-packages/cinematography`。本地工作区启动时自动安装缺少的随附默认技能，首次安装与旧工作区升级后即可在“我的技能”直接使用，无需手工导入，且不依赖启动时的工作目录。入口与参考资料一起保存为固定版本；未随附这些 ZIP 的开发环境不自动下载。

自动安装仅处理应用声明的默认包，不扫描或执行任意用户包。去重限定当前用户，优先检查保存的包标识及 `SKILL.md` 的 `name`，再核对内容摘要；已有手工安装、重命名或修改过的同标识用户技能保留原 ID、版本、正文、参考文件、分类、隐私和收藏状态，不覆盖、不额外创建副本。重复启动也不新增版本。ZIP 损坏或包名不符会报告初始化失败，不把缺少参考资料的半成品视为安装成功。

## 高级小说改编技能

`skill-packages/novel-adaptation/advanced-novel-screenplay` 是独立用户技能“高级小说拆解与短剧编剧”，分类为“短剧影视”。入口为 `SKILL.md`，版本为 `metadata.version: 1.0.0`；`references/novel-screenplay-spec.md` 保存完整创作要求，入口明确要求先读取该文件。外发包将两文件按相对路径打包为 `skill-packages/novel-adaptation/advanced-novel-screenplay.zip`，与摄影包一样在本地工作区启动时自动安装、按用户去重，不新增或覆盖原有内置技能；仍支持通过安装接口手工导入。

技能覆盖原著诊断、人物与全剧结构、分集大纲、正式文学剧本及十五项质量检查，区分原著事实与新增建议，维护人物、时间、道具、知情范围和伏笔连续性。默认文学剧本采用场次标头、`△` 动作与角色对白格式；用户指定阶段时只交付该阶段。章节分镜入口继续遵守应用的 JSON、原文对白和资产合同，不在结构化结果外输出文学剧本或分析。

与内置“小说拆解剧本”属于替代选择，通常选用其中一个即可，避免同时加载两套正式剧本格式。安装后的加入状态、版本及两个文件应通过详情核对；上下文加载通过不代表模型创作质量已验证。

## 展示与排查

### 打戏与玄幻特效专项

两个独立标准包均以逐镜结构2.3为底版，版本为1.0.0，分类为“短剧影视”：

- short-drama-editing/chixie-rusong-action-master：持械入宋·打戏动作导演大师版1.0，细化攻防因果、重心受力、接触/落空、群战主交锋、摄影轴线和跨段动作站位。
- short-drama-editing/chixie-rusong-fantasy-vfx-master：持械入宋·玄幻奇观特效导演大师版1.0，细化能力视觉语法、蓄势释放、尺度遮挡、动态受光、冲击反馈和持续余波。

每包独立包含SKILL.md、完整2.3导演参考、专项参考及视频执行规则，共四个Markdown文件。单选即可完成拆解，无需再选2.3或2.4。法术交锋可同时选择两个新包：动作版负责事件顺序、时长与攻防站位，特效版负责效果表现，沿用同一剧情结果、资产及输出合同；不为加载更多技能增加额度。

外层保持30秒，内部通常1–3秒、最长4秒，每段约1000–2000字有效导演正文。无对白的打斗/施法按动作与作用反馈切角，不强插说话人；有对白仍保留2.3的逐字原话、微推进、眼线、面部塑形和气息。允许细化笼统交锋/法术的摄影与表演，不新增能力、关键伤势、胜负或无依据的可见实体。首帧仅表示当段第一镜起幅，段尾状态通过既有连续性字段传递。

打包登记、安装和实际加载核验分别进行；离线传递测试不代表模型完成了动作编排或特效成片。仅导入技能不会改写旧分镜或触发媒体生成。

### 段内多机位快切技能

独立技能“高级短剧分镜·30秒段内多机位快切”位于 `skill-packages/short-drama-editing/short-drama-multicam-microshots`，版本 `1.0.0`，分类“短剧影视”。它承接高级改编的因果与情绪原则，专门设计30秒生成单元内部的小镜头；原“高级小说拆解与短剧编剧”和其他摄影技能不变。包内含入口、段内导演参考、视频生成专用参考，随附打包列表包含该新包。

每个内部角度/场景小镜头通常1–3秒、最多4秒；每1–3个主说话人角度穿插一次同场景反应、人物关系或叙事相关环境镜头。切镜和镜内微推进分别描述，逐字保留原对白并跨内部切镜连续发声，保持场景资产、摄影侧、站位、道具与主光连续。外层 `durationSeconds` 仍为30，不将内部镜头变成多个生成任务。

章节30秒脚本沿用禁止正文秒数/时间码的合同，节奏在内部规划中核算，视频生成专用参考再向视频请求明确时长目标。提示词加载与安装检查不能证明模型成片实现了精确节奏；需实际查看生成视频后判断。仅创建文本技能不会触发视频生成或自动改写历史分镜。

技能库默认按“最新发布”显示，清除筛选回到这一顺序；仍可选择“最多加入”或“最近更新”。分页在分类分组前执行，因此某分类在当前页显示的数量并不等于全库数量。按“最多加入”浏览时，新技能可能位于后续页，可切换“最新发布”或搜索技能名。

安装成功后应核对详情中的版本、分类、加入状态和辅助文件；不能只根据上传请求 HTTP 成功判断可用。只检查文本格式或上下文加载，不能证明模型输出的摄影效果已经通过。

## 持械入宋系列与技能额度

独立标准包 `skill-packages/short-drama-editing/chixie-rusong-v1` 的显示名为“持械入宋第一版”，版本 `1.1.0`，保留旧快切技能原文件与版本。新包包含入口、导演光学与对白参考、视频执行专用参考；在30秒段内1–3秒/最长4秒节奏上，增加切后微推进、焦段倾向、焦点与景深、移焦动机、克制的推拉变焦、人像透视与有动机的光线，以及对白意图、语速、情绪、停连和气息。表演说明与原文对白分开，长句跨切角持续，场景与声源身份连续。名称源于用户的参考观察，不代表已逐帧分析参考作品。

视线规则要求逐镜明确注视对象、画内/画外位置和高低关系，成对检查正反打轴线与目光匹配，区分摄影机对焦和演员视线，并保留符合话轮的自然反应。光影以整场主光基准、面部塑形、暗部层次和人物背景分离为依据，反打的受光从同一世界光源推导，不逐镜重置平光。首帧已有视线或光线问题时，应先核对参考图与镜头要求；文本规则与加载测试不能保证视频模型执行效果。

独立标准包 `skill-packages/short-drama-editing/chixie-rusong-plus-v2` 的显示名为“持械入宋plus第二版”，版本 `2.3.2`，包含入口、导演与表演规范、视频执行规则。单独选用即可覆盖改编、快切、微推进、光学、眼线、光影、表演及声音，不依赖第一版或额外摄影技能。动作相位、潜台词、听者反馈与声场服务同一场戏，不逐项增加停顿。一镜保留一种主运镜，允许一个可读表演与微推进同时发生。内部通常1–3秒、最长4秒，通常约10–15镜；30秒至少8镜只是数学底线，不是固定模板。每个单元约1000–2000字有效主导演稿，每镜六项合计通常80–140字，共用空间和主光只在整体设定建立，不逐镜复述。普通叙述优先转为画面，不新增朗读声轨；已确认旁白及明确OS原话照常保留。原话按实际话轮保留，同句多次出现不去重。每段独立绑定最新白名单场景与实际角色版本，不借其他场景或历史资产说明增添剧情。

随附包独立登记，保留第一版及其固定版本；安装接口导入修订包会形成独立技能，不自动替换旧项目选择。更新本人已有同包标识的ZIP技能可使用 `PUT /api/skills/:id`，JSON正文传 `archiveBase64`，由 `UpdateOwnedSkillArchive` 核对归属及包标识后追加固定版本，保留原技能ID及历史。该入口不运行包内脚本，也不接受替换他人技能。

30秒章节拆解实际加载的技能包含1–3秒、最长4秒要求时，首次请求使用 `directorScript: { setting, shots, ending }` 主稿合同。每个 `shots` 项独立返回 `durationSeconds` 和 `camera`、`start`、`performance`、`focusAndLight`、`end`、`sound` 六项文本。应用只将模型原文按数组顺序排版为 `videoMotionPrompt`，从落幅摘取 `timeBeats`，不补写细节或新增镜头；数字时长留作核算，不写入视频导演正文。剧情摘要、首帧和资产字段仍独立返回。文本检查读取逐镜真实核算值，报告超长、合计不符、未以1–3秒为主、空内容和有效主稿过短；格式要求随任务元数据保存，恢复任务时使用当次合同。

新任务记录 `storyboardExecution: planned-director-v1` 时，沿用同一模型、渠道及所选技能，先规划连续覆盖整章的原文行区间，再逐单元展开。规划和每个单元各最多一次定向修正；所有单元通过才发布完整结果，不将途中输出当作完成稿回填。核对原对白在对白字段及逐镜声轨中的顺序、重复话轮次数，校验白名单场景与角色身份；已有场景只按真实ID、标准名或明确别名准确绑定，不模糊借景。小幅镜长加总误差仅校准数值，不改写表演与台词。历史或普通单次生成任务仅保留结果及核对提示，不因恢复而自动补发请求。结构与长度检查不能替代对白、表演美感和成片质量的实测。

30秒模式只规定顶层单元的时长与格式，所选技能明确的段内镜长和切换频率仍须执行。摄影执行提示同时识别已选技能的名称与说明，导入后改名不应丢失摄影规则。以上规则与包加载测试验证文本和请求合同，不能保证视频模型执行效果。

章节拆解、画布分镜及短剧制作共同使用 `shortDrama` 配置，最多选择5项技能，文本上下文上限40,000字符；其他入口仍为4项/32,000字符。选满时每项仍有8,000字符预算，避免仅加数量导致单项预算由8,000降至6,400。已有截断、失败和超限报告保留；第6项不会静默忽略。视频阶段优先读取各技能的专用规则。

增加额度不代表创作质量必然提升：新增互补规则可以补足设计，重复或冲突规则会增加指令竞争；文本上限也不是模型剩余上下文或输出容量的保证。通常以本技能替代旧快切技能，再按需选改编、光影或连续性技能，不为填满额度而堆叠。加载测试验证文件完整与参数合同，实际对白情绪、口型及光学效果需要成片核对。

## 章节拆解调用状态

章节角色、场景与道具提取默认流式接收；渠道能力明确不支持流式时沿用非流式。桌面任务执行器保留本地运行策略，不误用托管服务的短超时。只有三类资产 JSON 完整且字段校验通过才写入结果；正文已完整接收但连接在收尾时中断，可保留校验通过的结果，上游明确报错或用户取消仍按失败、取消处理。

输出确实截断时最多自动续接一次，沿用原模型、渠道、流式设置与章节上下文，并验证续接断点和合并后的完整结构；不从头自动重发、不写入半成品。上游计费或后台成功不等于客户端已收到正文；未收到完整内容且无法续接的任务保留失败详情，不能仅凭计费记录恢复资产。

小说章节生成分镜时，章节页和分镜制作页显示最新一次拆解的“拆解技能调用状态”：逐项列出技能名称、版本、实际读取文件、加载成功、失败或跳过，以及上下文截断提示。技能缺失、停用、文件读取失败或入口为空时，会停止提交本次任务，保留逐项原因；不会忽略失败技能后继续提交。

调用状态默认收起，摘要显示拆解状态、已加载数量及失败、跳过或截断提示；点击或用键盘展开后查看文件、版本和错误详情。分镜制作页将其放在右侧产物预览栏，窄屏侧栏隐藏时可在编辑区底部查看，不占用脚本顶部空间。

已提交任务将明细保存在任务输入的 `metadata.skillLoadReport`，刷新后通过任务详情取回。技能加载成功与模型任务成功分别显示；“已加入拆解请求”仅表示参考文本已随请求提交，不代表模型逐条执行通过。记录读取失败可重新读取；没有明细的历史任务显示“未记录”，不会根据当前选择补造成功状态。提交前的技能准备失败仅保留在当前章节页面会话中。

章节请求保留场景、道具的完整身份目录供模型选择与任务恢复，不因资产标准名未逐字出现在原文就提前删除；人物仍按本章出镜边界处理。模型侧接收可用ID、标准名、类别及别名的紧凑白名单；只为本章相关资产附加简短外形与角色造型参考，不发送其他章节的整段制图提示词。白名单是可选参考，不是要求全部出镜。所选技能的段内节奏与详细导演稿要求在末尾输出契约再次明确。

30秒任务记录 `metadata.storyboardPromptReview` 文本核对规则。选择明确要求1–3秒、最长4秒的技能时，结果若不足8个不同内部镜头，或主导演稿不足1000字符，显示“脚本待修订”及具体段落问题，加载状态仍按原记录显示。历史任务仅根据其当时已发送的技能文本恢复节奏要求，不套用当前技能选择。前端结果核对本身不改写结果、不阻断保存、不触发额外模型请求；新规划任务的后台有界修正按上文执行。镜数和长度通过仍不代表实际镜长、表演或成片质量达标。

选择运镜或摄影机位设计类技能时，章节请求会追加摄影执行要求：把摄影机起点、触发动作、运动方向、停止落点与叙事目的直接写进“镜头与表演”，辅助字段摘录同一方案。人物走位不算摄影机运动；固定镜头仍可用于有依据的静观，不强制运动比例，也不允许不加判断地整章套用固定机位。规则用于首次拆解请求，已有分镜不自动改写，实际摄影效果仍需核对。

30 秒连续分镜的“镜头与表演”按约 1000—2000 字详细导演稿设计，逐镜展开起幅、动作过程、对手反应、空间变化、摄影动机、落幅切点与同步声音。此目标只约束主脚本的展开程度，区别于原文容量、对白量及资产附录；辅助字段只摘记同一脚本。原文简单时忠实优先，不编造剧情或重复描写凑字，篇幅不作为保存门槛，也不触发自动重写。实际生成仍受所选模型能力和 API 上限约束。
