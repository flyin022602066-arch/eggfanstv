# 本地 HTTP API

Wails 和浏览器开发模式共用同一套 `127.0.0.1` HTTP 合同。路由由 `backend/internal/handler/api.go` 统一注册，权威 OpenAPI 文件为 `backend/internal/handler/openapi.yaml`。

## 合同规则

- 无登录、Cookie 会话或租户选择；后端从本地 workspace context 解析唯一 owner。
- 成功响应为 `{ "code": 0, "data": ... }`；错误响应保留结构化 `code/reason/msg`。
- 写入接口限制 body 大小并校验资源归属；不信任前端提供的文件路径、模型能力或 provider 状态。
- 外部模型密钥由本地 provider config 管理，不在 API 日志或任务列表中返回。

自定义模型服务的配置仍由受保护的工作区配置接口提供给当前界面；运行时内存和生成请求可能包含凭据。浏览器持久配置缓存不保存 API Key、Secret Key 或自定义 Header，启动后从后端加载。内置 BeefAPI 继续使用后端凭据引用。配置导出会遮盖密钥和 Header 值；回填脱敏标记时必须匹配原渠道与 Header 名称，不能借用其他渠道的密钥。

模型目录通过本地后端读取。模型测试使用正常任务入口，等待最终文本或媒体结果才显示通过；测试会产生供应商费用，须先确认。测试结果不证明画布回填、媒体解码或最终账务结算。

`POST /assistant/ui-session` 返回仅驻留内存、绑定当前 owner 的 `token` 与 `expiresAt`。界面在到期前 30 秒重新签发凭据，同一身份的并发请求共用签发结果；重置或切换身份后旧响应不能恢复旧凭据。签发仍要求原有本机同源与 owner/桌面引导校验。

`POST /assistant/chat` 的响应头 `X-Beeftv-Turn-Admission` 区分 `rejected`（尚未调用业务轮次入口）、`unknown`（已经尝试开始轮次）与 `admitted`（已创建轮次）。仅明确的 `rejected` 或尚未发送消息的签发失败可按未接纳处理；缺少标记、网络错误或接纳后的断流仍需读取回执与画布确认。凭据续签和 403 失效处理都不会自动重放消息。

Windows WebView 的自定义渠道请求通过 `/ai/custom` 本地中转。桌面 CORS 预检须允许 `Authorization`、`X-Desktop-Token` 和 `X-Canvas-Upstream-*` 请求头；否则剪辑助手的流式文本请求及 Suno 渠道请求会在访问上游之前被浏览器拦截。前端中转必须携带桌面启动令牌；`Authorization` 只承载模型渠道凭据，不能替代该令牌，后端仍须校验 `X-Desktop-Token`。

Suno 音乐导演台也复用该中转入口，仅允许已发布的 26 个 `/suno/...` 原生路径及对应 GET/POST 方法。POST 限 JSON，GET 对参数名、ID 和分页做精确校验，不开放任意 `/suno/*` 代理；WAV 获取路径可返回音频或字节流，其余路径仍限原有响应类型。鉴权、自定义头脱敏与私网上游限制保持不变。参数和任务恢复合同见 [Suno 音乐导演台](./suno-music)。

## 核心路由组

`POST /tasks/:id/stop-local` 供当前桌面界面对单条排队中或生成中的视频任务执行“仅本地停止”。服务校验任务归属与视频类型，持久化为 `cancelled`、阶段为“本地已停止”，清除本地轮询计划与执行租约，并停止当前进程的等待。该接口不发送上游取消或查询请求，不声明上游已取消；保留上游任务 ID、输入和历史记录。已在本地停止的任务重复请求返回同一状态，其他终态不修改。旧 worker 的延迟轮询与完成结果不能覆盖已停止状态。重新生成由用户另行发起，可能产生新的上游费用。入口默认折叠在镜头视频右侧产物预览下方和任务详情的“高级任务操作”中。

`PUT /projects/:id/characters/:assetId/representations` 是主动替换角色参考图：校验本地图片资源归属后，在同一事务中创建角色新版本，并将本项目中该角色已绑定的镜头参考切换到新版本，保留引用顺序。已生成的旧产物标记为待更新但不删除文件；已提交任务的输入快照和运行状态不变。修改角色文字设定、声音或普通自动匹配不会擅自改写固定的历史版本。镜头缩略图和预览使用与生成提交相同的绑定版本，不使用角色当前主版本冒充提交图片。

`PATCH /projects/:id` 支持 `characterFacePresetsJson` 字符串，内容为 `{ "male": { "resourceId": "…", "fileName": "男主.png", "assetIds": ["…"] }, "female": { "resourceId": "…", "assetIds": ["…"] } }`。两项均可省略，`{}` 清空预设。接口校验项目归属、活动状态、图片资源归属与就绪状态，以及本项目角色绑定；允许先保存图片后绑定角色，同一角色不能绑定男女主两种面孔。`GET /projects/:id/core` 返回已持久化的预设。单张及批量角色生图提交前读取最新预设，将对应 `resource:` 图片放入 `referenceImages`，将人脸身份约束放入受保护的角色设定变量，沿用现有图片协议及产物回填。保存预设不会替换已有角色图或启动模型任务。

生成任务提交若包含当前渠道无法读取的本地素材，返回 HTTP 400、`reason=reference_media_requires_url`，不创建任务。`msg` 包含受影响素材的类型和序号；客户端可引导用户替换 HTTPS 链接或切换渠道。执行参数中的声音、水印等开关接受布尔值及其字符串形式，已有任务的同类参数也按相同规则读取。

`canvas.generation.propose` 是只读操作，返回的 `source` 包含 `canvasId`、`canvasRevision`、`modelConfigRevision`；模型键与配置版本来自同一次配置读取。提案不创建生成任务。

首次确认同时核对这两个持久版本、未保存的编辑和确认期间的变化。旧历史中没有 `source` 的提案需要重新提出。通过核对后，生成沿用已有模型解析规则，并使用确认时复制的提示词、节点、连线和全局参数。此版本合同不包含素材库独立更新、hydrate 时解析的动态角色版本或任意远端 URL 的内容字节变化。

`POST /timeline/render-plan` 接收时间线快照、不透明源标识和输出选项，返回版本化语义计划。源标识是 nodeId 或 resource id，不是本地路径。请求不得携带 ffmpeg 参数。该接口不做生成、不写资源、不创建任务。

`POST /timeline/renders` 接收同一套时间线快照和输出选项（宽高、帧率、采样率、是否烧录字幕），创建本机 ffmpeg 成片任务。选项进入任务输入并在执行时编译进语义计划。

`POST /timeline/transcriptions` 接收待转写素材编号和可选语言，创建字幕转写任务。只接受当前用户已上传完成的音视频。省略 `model` 使用本地 whisper.cpp；指定 `model` 使用已连接 BeefTV 账号的云端转写模型，必须由当前目录声明 `audio.transcriptions`。云端请求在服务端提取单声道 16 kHz WAV 后提交，最多 25 MiB；凭据不写入任务，排队期间连接改变会拒绝执行。云端识别按模型计费，结果以带时间的字幕返回。

`POST /depth-captures` 接收待处理视频素材编号，创建本机深度动作捕捉任务。只接受当前用户已上传完成的视频。可选 `nodeId` 指定结果节点，此时必须提供 `projectId`；任务保存目标节点并在完成后使用既有画布任务绑定操作回填。节点必须仍引用该任务，已删除或已改用其他任务的节点不会被恢复或覆盖。

深度任务继续在 `resultJson.resourceId` 返回结果资源，同时通过标准 `outputs` 提供视频素材及交付状态。历史深度任务也支持结果交付修复；没有记录目标节点的旧任务可通过 `canvas.task.bind` 绑定仍引用该任务的节点。交付暂时失败不会改写任务的成功状态，后台恢复仅重试交付，不重新执行深度处理。

若创建响应丢失，深度节点尚未保存 `taskId`，后台只在画布和目标节点匹配、节点 `taskClientOperationId` 与任务持久化的 `clientOperationId` 一致、节点仍为没有结果的深度视频节点时补上绑定。已有其他任务或素材的节点不会被覆盖。

这些任务在本机完成，提交时不用挑选模型。请求可以带 `clientOperationId`：同一确认重复提交会回到原来的任务；同一确认换成不同内容会被拒绝，不会再新建一条。

## 统一操作层与内置创作助手

### 视频预览

`POST /resources/:id/playback` 校验资源归属，为已上传完成的本地 H.265 或 MPEG-4 Part 2 视频按需准备 H.264 预览，返回最新资源状态。已在处理或已完成时复用现有任务和文件，失败后再次请求可重试。导入和应用启动不会主动转换全部视频。

`GET /resources/:id/file?variant=playback&proxy=1` 在副本就绪时读取预览文件。原文件下载和模型素材引用不改变。预览尺寸不超过 1920×1080，保持比例，不放大小视频。

`DELETE /resources/playback-cache` 清理当前用户已完成或失败的本地预览记录和副本，返回 `{ cleared }`。正在转换的预览和原资源不删除；其他用户的缓存不改变。

### 素材与操作

素材保存和批量同步会去除 `id` 首尾空白；未提供或仅含空白时生成 ID。数据库记录与返回素材文档使用同一个 ID，客户端后续更新应沿用该 ID。未识别的扩展字段和 `metadata.favorite` 会保留。

`DELETE /assets/:id` 校验素材归属及业务引用。清空回收站时传 `expectedStatus=archived`，在删除事务内再次检查状态；期间已经还原的素材返回 409 并保留。该参数只接受 `archived`，其他值返回 400。省略参数保留普通删除语义，仍须通过引用检查。

`GET /ops` 返回调用者当前身份可用的操作描述（含 JSON Schema）；`POST /ops/:op` 执行单个操作。
写操作必须带 `opId` 作为幂等键（同一 `opId` 同参数回读原结果，不同参数返回冲突），并按操作声明的
`expectedRevision` 做原子 CAS：缺少读取时的 revision、或 revision 已过期，都会被拒绝，不会覆盖别人刚写入的内容。
字段落点由画布能力描述符声明（例如生成类节点的可编辑提示词落在 `metadata.composerContent`，也就是画布编辑器
读取的字段），操作层不自行拼文档形状。

参数解析在所有层上都严格：顶层以及 `patch`、`nodes` 等嵌套对象出现未知字段时整批拒绝（`unknown_field`），
不会部分执行却推进 revision。schema 声明的 `params.operationId` 与请求信封的 `opId` 同时出现而又不一致时返回
`operation_id_conflict`，不会自行挑选其中一个身份。外部 MCP/CLI 的能力描述保留 `operationId` 作为稳定幂等键；
内置助手宿主自己生成幂等键，因此它看到的能力描述不含该字段。

### 助手回合归属

内置助手宿主调用 `/ops/:op` 时出示自己的宿主凭据 `X-Beeftv-Agent-Token`（由后端注入宿主进程，页面与
外部客户端拿不到），并带上后端在 `/assistant/chat` 中签发、随转发体下发的 `X-Beeftv-Agent-Turn`。
后端按该回合记录读取这一轮被验证过的范围，而不是信任任何调用方自报的列表：

- 会话默认范围是当前画布，加上当前画布文档里真实关联的素材与生成任务（沿用画布既有的媒体引用解析）。
- 界面上明确 @ 引用或附加的素材、画布在对话入口逐项校验归属后写入回合记录；当前画布模式中，额外画布只读。
- 当前画布模式拒绝跨画布写和无关素材/任务读取，并隐藏工作区级列举（`asset.list`、`canvas.search`）。只读与完全访问模式开放本用户工作区读取；完全访问允许带目标 ID 的跨画布写入，所有目标仍在领域服务校验当前归属。
- 已登记读写客户端与 owner 直连保持原有工作区读写能力；它们即使拿到 `turnId` 也不能出示归属，带上回合头会被拒绝。
- 回合只在开启期间接受归属；结算或撤销之后不再接受新写入，模型侧也无法自己生成授权。

内置创作助手的浏览器侧只使用同源代理：

| 端点 | 说明 |
| --- | --- |
| `GET /assistant/status` | 免身份的宿主状态查询（不含任何凭据）；未就绪时返回明确原因而不是空回复 |
| `POST /assistant/ui-session` | 签发短期限 UI 会话凭据；需本机同源，并且能出示 owner 凭据（或显式本地引导开关） |
| `POST /assistant/chat` | NDJSON 流式对话：`text_delta` 增量 + 一次 `turn_end` 结算；可带 `references: [{kind,id}]` 追加已校验的素材/画布引用；宿主凭据与模型密钥由后端注入，页面不接触 |
| `POST /assistant/cancel` | 取消指定画布正在进行的回合 |
| `GET/PUT /assistant/host/config`、`POST /assistant/host/start|stop` | 宿主生命周期：需 owner 凭据 + 本机同源；启动命令只取本机配置，绝不接受请求体传入的可执行命令 |

按轮撤销不依赖浏览器流或宿主的最后一条消息：轮前文档由后端在转发前落盘，变更摘要由该轮自己的写入回执重建，
因此浏览器断流（没有 `turn_end`）、用户取消或后端在回合中途重启之后，已经落地的助手写入仍然可以撤销。
宿主对模型请求与工具步骤各自有单轮上限（`BEEFTV_AGENT_MAX_REQUESTS_PER_TURN`、
`BEEFTV_AGENT_MAX_TOOL_STEPS_PER_TURN`），按轮独立计数、下一轮从零开始；总预算
`BEEFTV_AGENT_TOTAL_REQUEST_BUDGET` 默认关闭，只有显式配置才启用。

### 外部客户端连接

桌面设置的「外部 Agent」提供 Codex、Claude Code、Claude Desktop、Cursor 及其他 MCP 客户端的接入配置。Claude Desktop 使用开发者设置中的 `mcpServers` JSON；Claude Code 使用终端命令，Windows 命令需在 PowerShell 运行。保留其他 MCP 服务配置，连接时保持 BeefTV 开启。

配置固定使用随包 CLI 的绝对路径和 `BEEFTV_DATA_DIR`，避免客户端继承的环境选错工作区。Windows CLI 为主程序旁的 `cli/beeftv.exe`，不要把桌面主程序 `BeefTV.exe` 用作 MCP 命令。安装文件不完整时，`POST /agent-clients` 返回 412 / `cli_unavailable`，不签发凭据；重新下载并完整解压后重试。

MCP 使用官方 Go SDK 的 stdio transport；stdout 只写协议消息，启动诊断写 stderr。未发现运行实例时返回 `runtime_not_found`，不猜测默认端口；读取操作清单的启动等待上限为 5 秒。

使用运行时发现地址的 CLI/MCP 会在每次调用前重新读取当前实例，桌面重启换端口后，下一次调用连接新实例。显式设置 `BEEFTV_BASE_URL` 时保持固定地址。连接失败不会自动重发写操作，以免重复执行已送达的请求。

Windows 的运行地址描述文件位于用户目录的 `.beeftv/runtime/`，按数据目录的规范化路径摘要分开保存，并校验工作区身份。该位置在 AppData 外，客户端不再读取 AppData 中旧的 `runtime.json`，避免 Microsoft Store/MSIX 客户端的私有副本遮住真实实例。数据库和素材仍留在原工作区。升级后保持 BeefTV 开启，并在「外部 Agent」重新生成连接配置。

### 只读边界

桌面实例的已登记外部客户端使用自身 ID 与 Bearer 凭据访问 `/ops`、`/ops/:op` 以及业务目录列出的 REST 接口，不需要也不应持有桌面启动令牌。`GET /business/tools` 从当前挂载的业务路由生成目录，包含方法、路径、参数 Schema 和收费提交标记；只有目录中的方法与路径接受外部凭据。业务调用复用原 handler/service，继续检查归属、参数、余额与版本冲突。外部凭据不能签发客户端、换取 UI 会话、读取既有密钥或控制内置宿主、更新器。内置 UI 会话签发另需 Wails 绑定提供的独立 `X-Beeftv-UI-Bootstrap` 凭据；仅有 `X-Desktop-Token` 不足以签发。

外部 Agent 的执行审批由连接的 Agent 负责。新连接不再显示权限选择，缺省签发完整创作访问；历史明确签发的只读连接保留只读，可重新连接取得新凭据。MCP 从同一业务目录与共享操作目录注册工具。CLI 使用 `ops call <operation> --params '<JSON>'` 调用共享操作，使用 `business discover`、`business call --tool <id> --params '<JSON>'` 和 `business upload --file <path>` 发现、调用和上传。上传文件由外部 CLI 在本机读取，再经资源、技能或插件上传接口发送；后端不接受任意本机文件路径。模型配置读取会隐藏所有渠道密钥；带 `expectedRevision` 保存配置时，密钥字段缺省或为空会保留已有值。

只读是**操作层与 MCP 的策略边界，不是操作系统级隔离**：同一台机器上持有 owner 凭据的进程本来就能直接访问数据目录，
因此历史只读凭据和客户端主动选择的只读过滤只收紧该连接的工具能力，不能限制本机其他程序。

- 能力模式只由身份决定：已登记客户端的模式来自服务端登记，请求体与查询参数都不能提升或放宽它。
- `beeftv --read-only`（`ops list` 与 `mcp serve`）在客户端本地再次收紧：即使服务端返回了写操作，也只暴露 `readOnly` 操作。
- 服务端对写操作始终按登记权限拒绝只读客户端（`read_only_client`），不依赖客户端自觉。

内置 Pi 使用另一份按回合保存的权限：`POST /assistant/chat` 可带 `permissionMode: "read-only" | "canvas" | "full-access"`。缺省和旧记录为 `canvas`，不自动升权。只读能查看本用户工作区内容，不能修改、渲染或提交生成提议；当前画布模式保留当前画布写入范围；完全访问能读本用户工作区并修改所有画布。权限在 Go 开始回合时固定，补充输入不能改变，宿主恢复前重新读取；执行中的界面选择器显示该回合权限。技能仍只能读取本轮选定的固定版本，完全访问不开放宿主机 shell。

技能正文按 UTF-8 字节计量：单个正文最多 256 KiB，每轮所选技能正文合计最多 512 KiB，正文完整读取，不静默截断。超限返回 `skill_instruction_too_large`。技能校验发生在开始回合前；此阶段拒绝以及宿主读取请求体时返回的 `body_too_large` 均标记 `X-Beeftv-Turn-Admission: rejected`，客户端可以修改输入后再次发送。其他结果未知的错误仍需读取回执，不能直接重发。

跨画布回合在第一次写入每张画布前，于业务操作同一事务内保存原文。结算返回 `change.canvasChanges`；单次撤销先校验全部目标，再在一个事务内恢复。任何目标在该轮之后被修改，整组撤销返回冲突，不恢复部分画布。内置暂不提供非画布的 `conversation.message.attach`；外部调用保持开放。

## 生成确认与重放

`GET /assistant/history` 的每个轮次包含 `undone`，从当前用户和画布的持久化撤销回执读取。页面重开后仍显示已撤销；回执不存在或不属于该用户/画布时不泄露其状态。

历史轮次与流式 `turn_end` 均包含 `outputs: [{taskId, kind: "video", sourceRevision?}]`，用于展示本轮提交的免费本地渲染。Go 从成功的渲染操作回执恢复列表，重新校验任务用户、画布、类型及稳定操作编号，并覆盖宿主提供的同名字段。列表按回执创建时间排序，同时间以操作编号保持确定顺序；首版与后续修正版都保留。`sourceRevision` 来自提交渲染时记录的源画布版本，未知时省略。回执成功表示任务已接纳，不能代表成片已完成：页面继续使用已有的所属任务查询与认证资源播放接口。取消、回复失败或重开会话不会抹掉已经提交的渲染；读取列表不扩大助手工具权限。

`POST /tasks` 可在 `input.metadata.clientOperationId` 提交一次确认的稳定编号（8–128 个 ASCII 字母、数字、冒号、下划线或连字符）。相同用户、编号及完整原始请求返回已有任务；更换模型、提示词、素材、参数或项目时返回 409，不创建第二个任务。Trace ID 和 Request ID 不参与比较。任务回执丢失时以原编号和原请求重发；不要生成新编号猜测是否已接单。

旧任务若没有请求摘要，不能凭编号推断内容相同，因此拒绝重放，应先查询已有任务。此编号仅保证本地任务不重复创建，不代表上游扣费或取消结算已经确认。

## 任务诊断

章节分镜替换与角色候选写入可携带 `sourceTaskId`。服务端核对原任务、用户、项目、章节和生成类型，并将结果写入与稳定操作回执放在同一事务中。同一任务和内容重放返回原回执，不覆盖之后的人工编辑；更换内容返回 `409 operation_id_reused_with_different_payload`。分镜仍须提交批准时的 `expectedRevision` 与 `expectedShotIds`；冲突为 `409 project_revision_conflict` 或 `project_unit_shots_changed`。

`GET /projects/:id/chapter-apply-receipts?taskIds=` 查询最多 100 个任务的已提交回执。页面不以更新时间猜测是否写入；没有回执的分镜结果保留待核对，确认后可直接写入，不重新生成。

`POST /tasks/:id/query-provider` 用于取回失败视频任务的原有结果：校验归属、持久化的供应商任务 ID 和协议支持后，只查询状态及下载，不重新提交生成。恢复成功会保存任务结果并登记产物；正在处理时返回 `recovered=false`。没有原任务 ID 的记录不能凭本地 ID 自动找回。已发出但未取得回执的提交标记为 `submission_unknown`，阻止付费重试；明确限流、鉴权拒绝或尚未发送的请求保留对应错误类别。

NewAPI Channel 2 与 BeefAPI 视频的暂时下载断连会保留原任务 ID 并继续后台取回，自动恢复最长到任务开始后 24 小时；超出窗口后可在失败任务详情手动取回。任务日志接口提供脱敏的 `summary`，不返回原始 `message` / `payload` 内容；摘要不写回数据库。

任务列表与详情中的 `errorCode` 是 BeefTV 归类后的错误类别，不能当作上游原始代码。已识别的 SQLite 缺表/列、锁定、只读、I/O 和约束失败使用 `local_storage`，提示本地数据库无法读写、不自动重试；不能因为外层 HTTP 400 把它归为模型参数错误。判断只读取实际错误消息，不读取请求或提示词回显。新记录的失败任务可包含 `failureDiagnostics`：`source` 区分本地校验、上游 HTTP / 业务响应、本地结果处理及未知来源；`summary` 保存脱敏后的错误摘要，另带实际记录到的 `providerCode`、`httpStatus`、`param`、`requestId`、`providerTaskId`、`stage` 和 `capturedAt`。缺失信息不推断或补造。`createdAt` 是任务创建时间，`completedAt` 是结束时间，均不等于错误记录时间。

诊断字段在本地 schema v3 中以可空文本列保存，旧任务不补写原始错误，重试会清除上一轮诊断。任务列表、详情和画布的“复制排查信息”使用同一份诊断；复制内容不包含请求正文、提示词、凭据、素材 URL 或本地文件路径。`providerRequestId` 可能是供应商任务标识，在复制内容中标作“服务端关联 ID”，与 HTTP 请求 ID 分开。

镜头生成面板、任务详情和画布失败提示提供“失败日志”，显示同一份脱敏诊断及已记录的请求轨迹；镜头面板默认展开，画布节点可手动展开。上游 HTTP 或业务错误优先展示实际响应摘要、错误码、HTTP 状态和请求 ID，不被通用的“生成失败”或“提交结果尚未确认”提示覆盖；提交前的本地校验和提交后的界面同步错误单独标注。没有请求证据的旧任务不推断上游是否收到，不自动重新提交或收费。

`failureDiagnostics` 同时保留本轮执行证据：运行版本和平台、任务配置中的模型/尺寸/质量/数量、提示词长度、参考素材数量与图片大小、本地参考图限制，以及最多 8 次请求（首次及最近 7 次，省略数量另计）的发起状态、HTTP 状态、请求 ID、开始时间、耗时和字节数。任务配置不等于最终出站参数；协议可能转换或省略字段，核对实际发送值须凭请求 ID 关联请求日志。HTTP 200 仅表示收到响应；`executionResult=completed` 才表示生成处理完成。转后台回查时状态为 `pending`，同一次任务继续累积有界轨迹并保留首次请求。成功任务也保存这些证据，以便区分后续本地保存失败或画布应用失败（复制内容来源为 `client_result`）。请求轨迹覆盖统一 Provider HTTP 客户端；旧记录、未经过该客户端的插件请求或上游未提供的 ID 仍可能缺失，不能仅凭空轨迹推断未发送。

## 项目资产的集数筛选

分页读取 `GET /projects/:id/assets?page=1&pageSize=40&unitId=...` 时，`unitId` 为空表示全项目，章节 ID 表示对应集数，`__unassigned__` 表示未关联集数；可叠加 `category`、`mediaType`、`status`、`folderId` 和 `q`。归属由本项目已确认候选的 `resolvedAssetId` 与章节、以及镜头引用的任意历史资产版本确定，重复来源去重，不按名称推测或复制资产。

分页结果的每个资产提供 `unitIds`；`unitCounts` 是全项目已确认资产的集数计数，空字符串键表示未关联集数，跨集复用分别计入对应集数。`categoryCounts` 和 `folderCounts` 跟随当前集数范围，独立于分页与搜索。`GET /projects/:id/asset-candidates` 同样支持上述 `unitId`；候选只有镜头来源时通过镜头确定所属章节。所有查询保留项目与用户归属校验，不新增数据表。

## 本地模型配置恢复

`GET /workspace/model-config` 从工作区的 `local-model-config.json` 读取渠道、模型目录、默认选项和手动配置的模型调用凭据。桌面访问仍经过启动令牌校验；手动 Eggfans TV 渠道不能仅因沿用 `beefapi` 渠道 ID 而被当作企业托管渠道清空 Key，否则更换 WebView 数据目录后无法恢复调用配置。

企业连接托管的密钥仍不返回页面；火山资产上传 Key 仍只返回脱敏标记。配置恢复不拉取远端模型、不提交生成任务，浏览器缓存不是恢复手动渠道凭据的必要条件。

## 临时参考图片地址

`POST /resources/:id/upstream-url` 为当前用户已保存的本地参考素材准备公网 HTTPS 地址。配置 `CANVAS_PUBLIC_BASE_URL` 时优先签发地址；未配置时，图片、视频和音频自动通过 `https://uguu.se/upload` 上传到临时图床。该写入由生成流程触发，不在导入素材时批量上传，模型 API Key 与自定义请求头不会发送到图床。原件、资源 ID 与本地文件保持不变；图片上限 30 MB，视频和音频上限 128 MiB。Uguu 链接预计有效 3 小时，持久化链接在下次使用前检查有效期及远端可访问性；过期、剩余不足 5 分钟或已被删除时重新上传，保存最新 URL 和有效期。检查网络失败会阻止提交，不把未确认有效的旧链接交给模型。

图片节点的「节点信息」面板也可调用 `POST /resources/:id/temporary-image-url` 准备 Uguu 链接。该接口始终使用 Uguu，不受 `CANVAS_PUBLIC_BASE_URL` 影响；仍有效的链接直接复用，失效后自动重传并保存最新链接和预计有效期，便于复制给外部视频模型。Eggfans SD2 的图片参考使用此接口，仅提交公网 HTTPS URL，不调用私域素材库，也不接受 `asset://`。

佳速视频使用独立 `jiasu-video` 协议，仅提供视频能力，默认上游为 `https://www.gway.dev`。`/pricing` 模型目录地址转换为 `/api/pricing?surface=plaza`；本地配置读取和保存时迁移旧佳速默认地址，保留密钥、用户参数及其他渠道。任务配置中的 `videoJiasuFaceMode` 为 `default`、`off`、`light`、`heavy`，只在佳速视频任务中映射为可选 `face`，不复用 SD2 的 `native_face`。创建 `/v1/video/generations`，查询 `/v1/videos/tasks/{task_id}`，结果读取 `result_urls`。媒体统一使用公网 URL，本地原件通过临时图床准备有效地址，跳过所有私域 URI 同步；有本地资源记录时优先使用原件，不复用其他通道的资产 URI。`@图片N`、`@视频N`、`@音频N` 的引用名称与媒体数组顺序同步，首尾帧在 `images[].type` 内提交。H3 每段视频的 `duration_seconds` 来源于本地素材的实际时长，缺失时拒绝提交。

佳速 SD 的本地自动人脸遮罩在客户端创建任务之前执行，默认半透明网格，可手动调整或关闭。预览不上传图床；生成时通过现有 `POST /resources` 保存原尺寸 PNG 处理副本，任务图片引用指向副本的 `resource:<id>`，由原有媒体准备流程取得有效公网 URL。原件不替换，副本的失效链接重新上传副本。遮罩样式与区域按用户和原图内容缓存，区域随视频节点保存；本地配置 `videoJiasuFaceMask` 不进入 Provider 上游参数。仅协议 `jiasu-video` 的 `dola-sd-2.5`、`dola-sd-2.0` 应用此流程，H3 和其他渠道保持原来的素材路径。

佳速 SD 和 Eggfans SD2 D 的本地网格支持 50%、60%、75% 三档；50% 保留原密度，60% 和 75% 分别缩小网格间距，使横纵方向网格线约增加 20% 和 50%。视频设置和节点“人脸遮罩”均可切换，选择随各渠道配置与节点保存。`grid`、`grid-60`、`grid-75` 只用于本地处理与缓存隔离，不进入上游参数；不同密度生成独立副本，原始素材保持不变。

佳速返回的视频链接可以没有文件后缀。宿主保持原始链接及签名查询参数下载；响应为 `application/octet-stream` 或 `binary/octet-stream` 时，按文件内容识别 MIME，再保存本地资源。识别到 MP4 时使用 `video/mp4` 和 `.mp4` 文件名，未知二进制内容不会强制标记为视频。

SD2 视频任务的 `input.config.face` 为布尔开关。仅协议为 `eggfans-sd2-video`、开关开启，且准备后的素材实际包含参考图片、参考视频或首帧时，后端向 `POST /v1/videos` 映射 `native_face: true`。关闭、纯文本、仅音频和仅尾帧均省略；内部 `face` 不透传上游。A 至 E 不按模型过滤，D 的本地网格遮罩不覆盖原生开关。已保存的旧任务仍可读取 `videoNativeFace`；新任务显式的 `face: false` 优先于旧值。佳速和 Seedance 不使用该映射。

`GET /resources/:id` 的 `data.resource` 包含最近一次成功上传的 `temporaryImageUrl`、`temporaryImageUploadedAt` 与 `temporaryImageExpiresAt`（预计失效时间）；此读取不会上传或访问图床。上传记录持久化在工作区，重开软件后仍可读取。画布图片的“节点信息”显示未过期的完整 URL 并支持复制，过期后停止提供复制入口；有效期是图床的预计保留时间，远端提前删除仍可能导致链接不可用。

## Eggfans Seedance 与私域素材

默认上游是 `https://api.eggfans.com`。生成通过既有 `/tasks` 生命周期提交；`eggfans-seedance-video` 使用 `/api/v3/contents/generations/tasks`，`eggfans-volc-video` 使用 `/volc/v1/contents/generations/tasks`。两者均保留原生 `content[]` 和媒体 `role`，正文使用 `duration`、`ratio`、`resolution`、`generate_audio`、`watermark`。

| 本地接口 | 合同 |
| --- | --- |
| `POST /eggfans/private-avatar` | `{ config, operation, id?, body? }`；operation 为 `create/list/get/update/delete-group`、`create/list/get/update/delete-asset`、`auth-session`、`group-from-token`；返回解包后的 `Result` |
| `POST /resources/:id/eggfans-private-asset` | `{ config, body: { GroupId?, Name? } }`；校验资源所有者，自动上传 Uguu、创建资产并等待 Active；返回绑定 URI |
| `GET /resources/:id/eggfans-private-assets` | 读取当前用户资源的已保存绑定，不上传媒体 |
| `GET /volc-asset-library` | 读取当前本地工作区用户的火山资产 JSON 记录；自动创建本地资产目录，不查询远端 |
| `POST /resources/:id/volc-asset` | `{ name }`；使用独立资产上传配置，将本地图片的 Uguu URL 同步为火山 URI，并保存原图与记录 |
| `POST /eggfans/video-tasks/query` | `{ config, taskId?, pageSize? }`；只读查询原生或 Volc 任务；无 ID 时映射文档的 `page_size` |

私域 API 的 `model` 固定为文档支持的 `doubao-seedance-2-0-260128`（也允许 2.0-fast），与实际生成模型独立。保留 `Name`、`GroupId`、`URL`、`AssetType`、`Id`、`BytedToken` 等字段大小写；GET/DELETE 把路由模型放 query，PATCH 的 `Id` 与路径一致。上游业务错误不会当作成功。

私域同步失败会保留具体操作、HTTP 状态和请求路径。网关返回 `404` 与 `Invalid URL` 时提示私域接口未支持，不能据此判断视频模型的尺寸或时长错误；需由网关维护者确认接口支持。任务失败日志保留脱敏的上游响应，私域请求不会被记作视频提交，也不会更新视频任务 ID、轮询阶段或计入生成秒数。私域同步失败时停止生成，不自动切换为 URL 参考或 SD2 通道。

生成前默认将图片、视频和音频转换为 `asset://AssetId`；只有 Active 可提交。图片限制 30 MB，视频/音频限制 128 MiB；Uguu URL 约 3 小时有效。复用已持久化 URI 不依赖临时 URL；取消后保留 Processing 的 AssetId，恢复时继续查询。创建结果不确定时需在素材库查询并绑定已创建资产，避免重复创建。

私域自动同步仅适用于 `eggfans-seedance-video` 与 `eggfans-volc-video`。本地资源优先提交资源 ID，由后端按当前用户、Base URL、Key 和请求头隔离资产绑定，不直接采用素材上遗留的其他通道资产 ID。首次同步时先校验并刷新 Uguu URL，再创建私域资产；生成参数使用原生 `content` 中的 URI。`eggfans-sd2-video` 始终只使用 URL，两条通道不会改写对方的参考素材或协议参数。

本地模型配置启用 `volcAssetLibrary` 时，上述两个 Seedance 协议的图片同步改用文档中的山河火山资产服务，默认地址 `https://20nbifxd.magine.work/v1`。该服务以独立 `apiKey` Bearer 鉴权，不采用视频 Key 或 AK/SK。组查询为 `GET /assets/groups?page=1&page_size=100&name=...`，不存在时 `POST /assets/groups`，字段为 `name`、`description`、`project_name`。图片创建为 `POST /assets`，正文包含组记录 `group_id`（不是 `provider_group_id`）、`url`、`name`、`asset_type: Image`、`project_name`、`wait_for_active: true`、`timeout_ms: 120000`。必须返回 Active 与有效且一致的 `data.asset_uri/assetUri` 才进入生成；不以聚合记录 ID 拼接 URI。

组记录 ID 支持数字和字符串；数字 ID 按原生数字提交，精确保存为本地绑定记录。`project_name` 默认使用 `default`，其他值必须是火山已开通的项目名，不能使用本地项目标题。上游 `Asset://` 前缀统一规范为 `asset://`，资产 ID 保持原样。若已取得供应商资产 ID 但上次同步未确认完成，下次只查询 `GET /assets?page=...&page_size=100&provider_asset_id=...`，精确匹配并确认 Active 后补存原图和 URI；不重新上传或创建资产。

视频提交仍走所选 Eggfans Base URL 和视频凭据，`content[].image_url.url` 使用返回的 URI，`role` 保留原有生成语义。该文档的资产创建接口仅定义图片，视频和音频继续自动准备公网 URL 并保留原生 `video_url`、`audio_url` 与参考角色。SD2 不进入此流程。资产上传凭据保存在本地模型配置，GET 与浏览器缓存均只保留脱敏标记，后端保存时保留原凭据。

真人认证由用户打开 H5Link 完成；120 秒有效的 BytedToken 仅在当前弹窗内使用，换取 GroupId 后清除，不持久化到项目或日志。

## 明确不存在的端点

`/auth/*`、`/admin/*`、`/payments/*`、`/wallet/*`、`/public/canvas-shares/*` 以及云存储配置端点不属于本地产品合同。

旧内置 Agent 的 `/agent/*` 端点已随该功能退场，历史运行、偏好和记忆数据仍保留在本地数据库中。通用任务接口会按产品边界拒绝 `cloud_agent`、`cloud_agent_step` 和 `agent_memory_compact`，不会把它们当作普通生成任务执行。

内置 BeefAPI 连接成功后，同一份企业凭证用于渠道请求和模型目录。企业连接、模型目录、Provider/Protocol 与自定义渠道不受 Agent 退场影响。

内置 BeefAPI 的 Seedance 视频任务由本机后端上传参考素材后再向上游提交链接；浏览器不直接访问该上传接口，也不把整份参考文件放进本地 `/tasks` 请求。本机已保存的参考文件即使工作区已有公开访问地址，也仍由本机后端上传后再提交链接。失败时不会自动重提生成。
