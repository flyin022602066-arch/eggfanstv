# 憨包账号与飞狐接码

在「设置 → 模型管理」找到「憨包」，点击「账号管理」。本渠道使用独立 CLI 和 Edge/Chrome 浏览器登录资料，支持 Windows。它与普通 API Key 渠道分别配置。

## 登录与模型

填写账号标签，点击「登录 / 添加账号」，在弹出的浏览器完成扫码或手机号登录。生成时自动从组件账号清单中选择本地已登录、资料完整、未冷却或受限且本地剩余额度足够的账号；无需先手动选定生成账号。自动模式在每次新提交前刷新清单，依次轮换可用账号，不因组件的当前账号未变而反复选择同一个账号。「用于生成」设置优先账号，优先账号不可用时轮换其他可用账号；「恢复自动匹配」清除优先设置，保留登录资料。受理后的查询固定使用回执中的实际账号，不改用后来选定的账号。提交失败不会自动换号重复生成；下一次明确提交才重新选择，避免重复计费。

组件确认保存登录态后会自动关闭登录窗口；这本身不表示崩溃或风控。账号管理持续显示本次登录成功、未完成或主动结束等待的结果，切换接码页仍可查看。只有组件明确返回 `logged_in=true` 才确认登录成功；打开窗口、调用返回成功但没有登录确认，都不能当作已登录。登录成功后的账号列表刷新失败单独提示，不覆盖已保存的登录结果。关闭窗口或浏览器连接中断时显示组件返回的原因；没有上游限制提示时不推断为风控。

账号卡片同时显示标签与用户名，用户名对应组件账号的 `id`。「选择管理」在卡片标记当前管理账号，并展开底部额度设置；设置区同时显示该标签与用户名，避免编号标签与用户名无法对应。额度管理独立于登录标签和生成优先账号。体验订阅等账号可按实际额度修改每日条数、每日秒数；保存仅修改选中账号的本地阈值，保留已有消耗计数，显示保存结果或具体错误，不自动购买套餐或修改上游额度。

手机号和验证码需要手动填写；组件不提供自动填表命令。等待登录期间仍可使用已保存的配置取号和收码，但不能修改设置；需要修改时点击「结束登录等待」，保存后再打开登录窗口。结束等待或关闭账号管理弹窗会中止本次登录请求，不删除账号资料或释放接码订单。「检查登录」会联网校验，本地账号清单中的已登录标记不代表当前网页会话一定有效。自动选账号不会联网校验全部账号，不会绕过上游额度、解除冷却或重置计数；没有可用账号时显示未登录、冷却受限和本地额度不足的数量，并明确尚未提交。

| 模型名称 | 实际模型参数 |
| --- | --- |
| Seedance 2.5 | `seedance_v2.5` |
| Seedance 2.0 Mini | `seedance_v2.0_mini` |
| Seedance 2.0 Fast | `seedance_v2.0` |

- 时长为 4～30 秒整数，默认 5 秒；0 不是自动时长。
- 比例支持 `16:9`、`9:16`、`1:1`、`4:3`、`3:4`。
- 分镜制作手动选择的视频画幅按项目记住，后续镜头、章节、重新进入页面和重启后沿用。首次使用取项目画幅；切换模型时按该模型支持的比例归一化，不覆盖手动保存的偏好。视频画幅与图片尺寸、其他项目分别保存。
- 支持文字生成和图片参考生成，最多 9 张参考图。画布和项目统一保留参考图顺序，将原始图片交给憨包组件，不按单图或合计 4 MiB 在本地拒绝，也不额外缩小 4K 原图；开启本地人脸处理时使用处理后的图片。图片上传、压缩及上游大小限制由憨包组件处理，组件返回的错误保留在失败详情中。
- 不支持生图、参考视频、参考音频、分辨率、FPS、随机种子和负面提示词。
- 视频默认同步生成声音，画布与分镜生成设置统一显示「同步声音已开启」，不会向组件追加未提供的声音开关参数。
- 生成设置可选择本地人脸遮罩：关闭、半透明网格（50% / 60% / 75%）或马赛克。画布节点支持预览及手动框选；提交前处理参考图并保留原始资产，处理后的图片交给憨包组件。憨包的偏好、框选及处理图缓存与其他渠道隔离，不向组件发送 `face` 或 `native_face` 参数；未检测到人脸时保留原图，识别失败则提示框选或关闭后重试。
- 套餐标签、每日条数和秒数是本地调度阈值；重置计数不会增加上游真实额度。

「调用参数」允许选择 `auto/canvas/chat`，网页版本默认 `20800`，PC 版本默认 `3.43.2`。画布尝试次数默认 1；调大可能由组件内部重复提交并额外消耗额度。

保存调用参数或接码设置后，按钮旁持续显示「已保存」；只有后端确认写入才显示成功。保存失败显示具体原因。后台状态刷新失败会单独提示，不影响已完成的保存；保存期间继续编辑的内容会保留，并标记为尚未保存。

## 飞狐接码

入口只存在于憨包账号管理中。填写用户中心「API对接」的 API账号与 API密钥，保存后点击连接。在「平台名称」填写名称（如「豆包三次」），点击「查询项目 ID」或按回车，结果显示项目名称、ID、价格和可用状态；选择已审核的豆包或憨包项目后自动填入并保存项目 ID。其他平台可查询，不用于憨包账号取号；手动编辑项目 ID 后仍需点击「保存接码设置」。API账号使用普通输入框，API密钥使用密码输入框；两项均不是网页登录的账号密码。默认 HTTPS 基础地址为 `https://my.feihu2026.com/api/sms`；账号或密钥输入留空会保留对应原值。

取号时绑定憨包账号标签，直接选择「取号来源」，可筛选运营商、省份、实卡/虚卡、包含或排除号段；高级筛选支持指定号码、作者、对接码和混入香港号码。没有预置作者或佣金账号。`isp=hk` 为仅香港，`hk=1` 为混入香港，两者含义不同。

API账号对应官方文档的 `api_key`，通过 `user` 传输；API密钥通过 `pass` 传输。高级筛选中的 `author` 是对方的网页登录用户名，用于分成归属，不是 API账号或密钥，不影响号码来源。本模块默认明确传 `mode=1`，使用平台公共池，不继承飞狐账号的未知默认取号模式；手动选择 `mode=2/3` 时保留该模式。使用对接码前须先在飞狐平台加入该项目的对接码。收到「未加入对接码」错误时可切回平台号码，再手动取号；软件不自动切换或重复购买。指定手机号时平台会忽略对接码。

余额 `money`、最大取号数 `max_num` 和可用取号数 `available_num` 是平台账户统计。可用数量代表并行取号配额，不是当前项目实时号源库存，不保证当前筛选条件一定可取号。平台拒绝请求时，界面保留失败步骤、HTTP 状态、上游业务码及脱敏后的 `msg`（缺失时读取 `message`），不把无号、余额不足或其他原因相互替代。取号失败不自动重试、不创建虚假订单；接码错误只显示在接码页。

目前为辅助登录流程：填写憨包账号标签 → 取号 → 打开该账号登录窗口 → 手动填写手机号并发送验证码 → 自动或手动收码 → 手动填写验证码完成登录 → 生成时自动匹配可用账号。自动收码仅轮询已有订单，不会自动发送验证码、填写网页或完成注册。

短信轮询间隔至少 10 秒；只在用户启用自动收码时轮询，关闭弹窗即停止前端轮询。可手动查询、释放或拉黑本模块创建的订单，不提供全平台释放、按任意订单或号码查询等通用接码入口。后端取号前再次核对项目名称、ID 和审核状态；订单绑定原平台凭据和项目，不能用另一平台账号操作。存在等待短信的订单时，先收码或释放，再修改接码凭据或项目。

收码状态遵循官方文档：`1` 等待、`3` 已完成、`4` 失败、`5` 已释放、`6` 超时；结束状态停止轮询。未完成订单用完应释放，以归还取号配额；已经收码的订单不可撤销。拉黑仅对当前平台账号和该项目生效；进行中的订单同时释放，已完成、失败或超时订单保留原状态及短信记录。

后端使用表单 POST：`login` 传 `user/pass`，其他接口传 `token`；同时校验 HTTP 状态和上游业务 `code=200`。凭据不放 URL。平台文档见 [飞狐 API 文档](https://my.feihu2026.com/document)。

## 本地数据与任务

发布目录 `tools/hanbao` 保存 CLI 与原始参数合同。CLI SHA-256 固定为 `1e548f69030af8790d20a0fcd42ec2207a3e35b15ecb4c70021f4e24aad72866`，运行前检查，不执行被替换的文件。管理员可通过 `CANVAS_HANBAO_CLI` 指定相同哈希的组件文件。

账号和加密配置保存在当前工作区的 `hanbao` 子目录。子进程同时隔离 `DOUBAO_BASE_DIR` 与 `APPDATA`，不自动迁移其他软件的账号。飞狐配置和短信订单使用工作区密钥加密；访问 Token 只保留在后端进程内，设置读取仅返回是否已保存凭据。

生成沿用持久任务队列。提交后将完整 `submit_id` 和返回的实际 `account` 一起保存，并在当前任务租约内原子登记提交记录。组件可能轮换账号，查询不会改用用户后来选择的账号。网络中断、`query_error` 和等待超时继续回查原任务；提交响应不确定时停止自动重发。账号管理与生成互斥，已受理的活动任务也会阻止修改账号配置或清理浏览器资料。

画布和任务详情显示实际执行阶段：等待本地组件、正在提交、已提交并查询状态、上游排队、上游生成、取回结果和本地保存。查询开始与返回结果分别显示时间；只有本轮查询明确返回排队或生成状态时才显示对应状态。查询异常显示「查询暂不可用，稍后继续查询原任务」，未知状态显示继续查询，不推断上游仍在生成。活动憨包任务不显示未经上游确认的百分比，已受理回执与阶段原子保存。

固定组件自身会在查询累计等待超过 45 分钟且未找到结果时合成失败消息；这不是上游明确生成失败。遇到这条固定消息时显示本地组件查询超时，保留回执继续查询，不重新提交。历史已记录的相同消息在详情中区分为本地查询超时，可通过「取回结果」继续查询；上游明确失败仍保留失败状态和原因。

回执支持进度文本混合、多行 JSON 以及写入标准错误流的结构化响应。存在完整任务号和实际账号时，即使组件以非零退出码结束，也保存回执并查询原任务；不能用进程退出码覆盖已受理回执。缺少回执时标注「待确认」，保留脱敏后的组件步骤、业务码、退出码及原因，不自动换号或重新提交。失败日志区分「本地憨包组件」「本地参数校验」与已查询到的「上游业务响应」；组件返回的 `code=3` 不自动解释成某个上游原因。仅记录结构化错误中的必要信息，浏览器会话、凭据、提示词、原始进程日志和本地路径不进入诊断。

与原组件 SDK 一致，提交回执优先采用 `submit_id`；缺失时采用 `conversation_id`，并始终绑定回执中的实际账号。数字型会话号按原始十进制文本读取，不经过浮点转换，避免长会话号失真而无法查询。已受理但本地等待结束时保留原回执；查询返回数值型 `query_error=0` 不视为查询失败。

固定版本组件明确返回「画布连续 N 次生成失败……这条先跳过，可稍后重试或换个账号」时，表示组件已经确认该次生成失败，直接展示原因，不再误标「待确认」。旧记录仅在保存了这条明确诊断、模型属于憨包且没有受理回执时修正展示和重试判定；其他不确定记录保持原状。

失败视频可在分镜制作的产物预览下方点击「重新查询」，或在画布「任务详情」、任务中心点击「取回结果」，通过 `POST /api/tasks/:id/query-provider` 查询。失败任务的本地 ID 和已记录的上游 ID 保留展示；即使前端没有上游 ID，也保留查询入口，由后端先从 API 日志和原路由提交记录检查回执。查询固定使用回执中完整的 `submit_id` 与实际 `account`，包括原样保留 `cv:` 画布标识；只执行 `query_result --once`，不再次提交生成。成功后下载视频、保存本地素材并回填原画布；仍在处理中或临时查询不可用时恢复原任务自动查询。查询明确返回失败时更新原因，包括组件返回的 `fail_reason`，不会误报为仍在生成。没有完整回执时持续显示无法自动查询的原因；`list_task` 仅为组件本地缓存清单，不能保证找回未返回回执的画布任务，也不能仅凭缺少本地回执断言上游未生成。

不支持上游取消；「仅本地停止」结束本机等待，上游仍可能运行或计费。不要把进程退出、HTTP 成功或本地登录标记当作生成完成；仅在 `gen_status=success` 且存在视频 URL，下载和本地资源保存成功后交付结果。

## 本地 HTTP 接口

这些接口使用当前本地工作区权限与 BeefTV 的 `{ code, data, msg, reason }` 信封。

| 方法与路径 | 请求与用途 |
| --- | --- |
| `GET /api/hanbao/status` | 读取组件可用性及脱敏设置；不会登录、取号或生成 |
| `PUT /api/hanbao/settings` | 保存账号、网页调用参数及飞狐配置，最大 16 KiB |
| `POST /api/hanbao/accounts/:action` | `accounts/login/checklogin/open/logout/delete-account/set-plan/reset-quota`；JSON 为 `account/plan/dailyLimit/dailySeconds`，最大 4 KiB |
| `POST /api/hanbao/sms/:action` | `connect/info/projects/orders/receive/message/release/blacklist`；JSON 为 `account/orderId/name/filters`，其中 `projects` 使用 `name` 查询平台项目；最大 8 KiB |

账号操作忙时返回 HTTP 409、`reason=conflict`。无效参数或平台调用失败返回真实失败状态，不伪装业务成功。CLI 登录最长等待 300 秒，前端请求超时另留退出时间。
