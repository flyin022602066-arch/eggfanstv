# 本地模型配置持久化

本地桌面模式的模型渠道不再只依赖浏览器 `localStorage`。前端启动时通过 `/api/workspace/model-config` 读取本机快照，渠道发生变化后自动保存；后端将快照原子写入 BeefTV 应用数据目录的 `local-model-config.json`。

- 配置文件位于应用数据目录，不进入 Git，也不随前端静态资源更新覆盖。
- 写入采用临时文件 + `rename`，文件权限为 `0600`，目录权限为 `0700`。
- 同一工作区路径上的多个配置句柄共用一把进程内锁；revision CAS 与脱敏密钥保留跨句柄串行。损坏、`null` 或非对象的现有主文件不会被新写入替换。
- 带 `id` 的渠道只按相同字符串 ID 保留密钥；对不上的脱敏占位会拒绝写入，不会把 A 的密钥写进 B，也不会把占位符存成密钥。
- 工作区路径只把「尚未创建的后缀」当成可恢复；符号链接环或权限/非目录错误会失败，不会为同一目录生成两把锁。
- 内置 BeefAPI 渠道由本机连接流程管理，授权密钥单独加密保存在工作区，不经过模型配置接口、导出或页面。
- 其他手动渠道的 API Key 仍保存在本机配置文件中，不应提交到仓库或日志。
- 手动配置的 Eggfans TV 渠道与企业托管渠道分开处理：手动渠道从本地快照恢复 Key、Base URL 和模型目录，不依赖旧 WebView 缓存；企业托管密钥仍不返回页面。
- 手动渠道拉取的新目录、模型能力与默认选择一并保存，后台不会用旧目录覆盖。拉取成功后等待本地写入完成才提示“已更新并保存”；保存失败会明确提示，现有目录仍留在页面供重试。
- Eggfans TV 启动后会后台刷新一次 `/pricing` 模型目录，并将非空结果保存到本地；拉取失败或返回空目录时保留上次缓存，不影响进入工作区，也不会提交生成任务。
- BeefAPI 可用模型以连接后拉取的目录为准，不在仓库中写死。

文本选择器按模型能力筛选，排除图片、视频、音乐、向量和重排模型；支持上传参考图不代表模型能够生成图片。启动时会修正旧目录中已知文本模型被误标为图片的记录。

首次使用新桌面构建时，如果旧版本仍有浏览器渠道配置，前端会自动迁移到本地快照；后续重装前端资源不会清除模型配置。

画布助手也从这份快照读取模型和渠道凭据。手动渠道只有 `models` 列表、没有对应 `modelProfiles` 时，助手可跟随已选定的默认文本模型，使用渠道指定的对话协议；OpenAI 格式默认使用 Chat Completions。已声明的能力和协议优先，禁用渠道、非文本模型、不支持的协议或缺少密钥仍不可用。内置托管渠道继续使用其明确的模型目录。

## 分镜制作的模型记忆

章节分镜和章节资产提取共用按项目保存的文本模型选择（`projectWorkflowModels[projectId].chapterText`）。首次使用跟随模型配置中的默认文本模型，手动选择后立即保存，关闭弹窗、切换页面或重启后仍优先恢复上次选择；不会改动全局默认模型。列表只包含文本模型，图片、视频、音乐等模型不能用于提交。已记住的模型被删除或改为其他能力时，会提示重新选择并阻止提交，不会自动换成其他模型。

生成设置中的模型选择立即保存到 `projectWorkflowModels`，随同本地模型配置持久化。每个项目分别记住分镜图、动作预演和镜头视频的最后选择，切换镜头、章节、页面或重启软件后优先恢复该选择；从未选择过时才使用项目默认模型或全局默认模型。修改模型不清空未保存的提示词。

已记住的模型从渠道目录中移除或不可用时保留原选择并提示重新选择，阻止提交，不静默替换为默认模型。该偏好只保存渠道与模型标识，不改变其他项目的选择或全局默认模型，也不进入模型上游请求。

## Windows 项目工作区

项目内运行的 EggfansTV 统一使用项目根目录下的 `.local/EggfansTV`。通过 `run-eggfans-tv.cmd` 启动，或直接打开项目内的开发构建、打包版本，均读取同一份模型配置、SQLite 和资源；不以当前终端目录或浏览器缓存决定工作区。显式设置的 `CANVAS_DESKTOP_DATA_DIR` 仍优先。

旧工作区迁入项目目录前，先关闭软件并备份源目录和目标目录，再迁移完整工作区。只复制 `local-model-config.json` 会遗漏项目、任务、资源和工作区密钥；不能通过启动一个空目录来代替迁移，也不能将旧目录覆盖到已有项目的工作区。
