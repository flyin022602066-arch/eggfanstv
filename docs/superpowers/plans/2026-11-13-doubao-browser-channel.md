# eggfansTV 豆包浏览器渠道实施计划

**Goal:** 新增独立本地视频渠道，持久保存 100 个隔离浏览器环境，预热和调度时保留两个空闲环境，提供安全的批量网站数据清理入口。

**Architecture:** Go 本地领域服务管理工作区边界和 Node 子进程；Node 用 Chromium 调试管道管理本渠道专用浏览器资料、账号池与原生画布请求。项目和画布沿用任务中心，受理回执先持久化，恢复只查询原任务。

**Tech Stack:** Go、Node 24 内置 API、Chromium CDP pipe、React/TypeScript、现有 http 模块。

**Spec:** 用户本轮要求及 .local/cache/hanbao-reference-analysis-20261113.md 中已核对的协议。

## 约束

- 产品文案使用 eggfansTV；独立协议 doubao-browser-video，不改憨包 CLI 合同。
- 总环境数固定 100，至少保留 2 个空闲；100 个资料不等于同时启动 100 个浏览器。
- 无法创建真正上游身份或读取可靠额度时如实报告；不伪造登录、余额或重置成功。
- 批量清理只涉及本渠道、无未完成任务的环境；完整网站数据清理会清除 Cookie 和登录状态，清理后重新判断可用性。
- 未知提交和原任务回执不能因清理、换号、重启而丢失或自动重发。
- 用户已追加授权：使用项目现有真人人像进行一次真实参考视频生成；不把隔离环境当作有额度账号，不通过清理或换环境绕过上游配额。
- 平台明确拒绝真人素材时保留拒绝原因；只有供应商正式支持的授权素材方式可作为后续路径，不通过遮挡人脸规避审核。
