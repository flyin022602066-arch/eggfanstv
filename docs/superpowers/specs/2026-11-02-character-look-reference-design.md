# 角色多造型自动参考首版

目标：同一个角色的服装、年龄、伤态等造型分别选图，镜头固定版本，视频提交复用同一选择。用户已批准在功能分支实现并测试。

## 数据与边界

- 沿用 Asset / AssetVersion / AssetRepresentation。版本增加独立的 referenceProfileJson，保存造型分组、名称、外观描述、适用与排除线索、自动参与、定稿及默认标记。图片和原设定不可因标注发生修改。
- 同造型的多次重绘归为一组，只用定稿；历史未标注版本根据原设定建立暂定分组，无法判定则待确认。不同版本的图片不能隐式回退。
- 镜头引用增加选择来源、状态、理由、锁定和判定时的脚本修订。选择结果与 reference 的版本一起原子持久化；替换只影响该角色的 reference，不触碰其他角色及输出/首尾帧。
- 目录读写、引用替换都在 project domain 校验归属与项目活动状态，repository 执行查询/事务。对写入增加项目修订及脚本修订校验。正在生成的镜头不能换绑定。

## 流程

1. 角色卡进入“造型与版本”，查看所有历史定义及图片；标注分组与定稿，可创建空图造型，上传图片或使用现有生图参数显式提交图片任务。
2. 镜头右侧提供识别本镜、识别本章、仅待确认。文本模型结合章节、连续镜头、出镜人物及造型目录给出 versionId、依据和待确认项；规则拒绝不存在/外来 ID、缺图、多版本冲突及无证据结果。模型自报置信度不单独决定是否通过。
3. 手动选择自动锁定；解锁允许重新识别。同场景连续镜头沿用造型，闪回/换装/年龄/变身变化必须重新匹配；变身或同人双版本同框超出首版的单版本绑定能力时明确待确认，提示拆镜头。
4. 生成前检查 pending、缺图和多版本冲突；有选择结果时保证脚本修订仍匹配。预览与真实请求共用参考包，记录版本、图片资源及选择依据。所有视频任务由用户点击。

## 验证

本地测试覆盖版本目录/归属、分组定稿、旧绑定保留、锁定、并发冲突、生成中跳过、缺图不回退、语义结果校验及模型数量限制。浏览器使用隔离模拟数据，验证角色造型管理与右侧选择；不调用真实模型，不操作用户项目数据。
