## 3. 授权决定接入方式

RuiC 的 LICENSE 将 MIT 范围限定为其代码、样式、脚本和文档，明确排除图片、原始记录及原站衍生名称、分类等。README 也说明图片与原始数据不属于 MIT。

两个原站允许创作、商业作品、编辑及逐张作为生成参考；明确禁止批量下载（含工具自动获取）、转载、再分发、转售图片本身。不能因为 GitHub 收录了素材就把它们全部复制、压缩、打包进 BeefTV，也不能把改成远程热链视为已经取得整库再展示许可。

可选路径：

1. 推荐的先行路径：实现自己的模板库及本地导入，提供原站入口；用户在原站逐张选择下载后导入，或导入自有授权图片。保存为可重复调用的姿势、服装或组合模板。原站未授权的图库不预装、不批量抓取。
2. 全量内置路径：取得原作者允许第三方展示、缩略图/原图分发、离线打包及更新方式的授权后，以固定版本导入完整素材包。此路径能实现所有条目直接在画布里浏览和调用。
3. 纯文字预设路径：不带参考图，只用独立编写的动作/服装描述；接入最轻，但不满足精确姿势与服装细节控制的目标，故不推荐作为主方案。

## 4. 推荐的产品设计

### 入口与目录

- 图片节点创作面板增加“参考模板”，放大编辑面板提供同一入口；复用 AppModal 与当前主题 token。
- 分为姿势、服装、我的组合；人像若明确纳入，则作为独立分类及独立数据源审查，不隐式扩大首版范围。
- 搜索名称/标签；姿势按人数、动作、视角筛选；服装按分类、品类、颜色筛选。支持收藏、最近使用。
- 只呈现已导入或获授权的数据；明确区分完整目录、可用图片和加载失败。授权全量版本使用分页或虚拟网格、懒加载缩略图。

### 应用到生图节点

- 默认把所选图片接入节点引用链，同时附上可编辑的参考用途说明；只有文字的条目可单独追加提示词。
- 组合模板保存姿势项及视角、服装项、可选角色参考、用途说明和来源版本；一次调用复用已有资源，不重复上传图片。
- 用途描述引用实际图片编号/token：角色图控制身份，姿势图控制身体动作和构图，服装图控制款式、颜色、材质，避免把人台脸或灰色皮肤作为角色外貌要求。
- 保留原主体提示词；替换同类模板只更新模板拥有的引用和提示块；移除模板不删除用户自行加入的图或文字。
- 应用模板只修改编辑内容与引用，用户点击“生成”才提交任务。

### 模型能力

已有普通图片生成链路支持 referenceImages 并校验 maxImages；模板必须合并已有参考后再校验。超限应让用户替换/取消，不能静默丢图或自动改模型。

图片参考是模型输入，不等同于 ControlNet。姿势图是人台线稿，不含可直接编辑的 3D 骨骼数据；现有本地 OpenPose 提取可作为用户显式选择的后续扩展，不能默认触发、自动安装模型或宣称每个生图渠道都支持骨骼控制。

### 项目隔离与持久化

- 系统模板是独立目录，不灌进全局项目资产；用户只在当前项目实际应用某个模板时建立项目引用。
- 我的模板与偏好按现有用户 scope 隔离；图片和模板 JSON 使用资源服务/localforage，不将媒体或大清单存进 localStorage。
- 模板元数据保留稳定 ID、类型、名称、标签、来源、许可状态、版本/哈希和资源 storageKey。跨项目可浏览公共模板，但项目资产列表仍只显示本项目绑定资源。
- 执行前捕获项目、节点和用户 scope；导入过程中若切换项目/节点或目标已删除，取消应用，不把图片挂到新目标。
- 区分仅本地缓存和后端已持久化，失败向上提示，不显示虚假的保存成功。
- 模板删除与物理资源清理分开；资源删除沿用项目、画布、任务引用保护。

## 6. 实施后的验证标准

- 数据：稳定 ID 去重、分类数量、4 视角特例、版本固定、授权标识与图片缺失。
- 应用：实际参考图和文字同时进入节点；保留已有主体内容；重复应用不重复引用；替换/移除仅影响对应模板。
- 隔离：节点/项目/用户切换时不串引用，公共模板不使其他项目资产出现在当前项目。
- 持久化：刷新恢复、资源复用、本地降级提示、取消及失败无半成品写入。
- 能力：合并已有参考后的模型数量限制，纯文生图模型不能误显示参考已生效。
- UI：隔离模拟数据验证入口、搜索、筛选、收藏、视角切换、应用及移除；明暗主题和浮层事件不触发画布缩放/快捷键。
- 使用最小充分的 Bun 专项测试与必要构建；不调用真实生图，不触碰用户真实项目素材。
